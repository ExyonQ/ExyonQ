# ExyonQ v0.4.9

Published release. Linux binaries and both container images, `linux/amd64` and `linux/arm64`. No `:latest` tag.

- GitHub Release: https://github.com/ExyonQ/ExyonQ/releases/tag/v0.4.9
- Server image: `ghcr.io/exyonq/exyonq:0.4.9`
- WordPress image: `ghcr.io/exyonq/exyonq-wordpress:0.4.9`
- Binaries: `exyonq-linux-amd64.tar.gz` and `exyonq-linux-arm64.tar.gz`

A static route denies `.php`, `.phtml`, `.phar`, and dotfile names. `.well-known` stays reachable. Set `allow_sensitive = true` on that route to serve one of those files.

The stock WordPress `.htaccess` compiles. `E=HTTP_AUTHORIZATION` does not reject the file. `Authorization` reaches PHP as `HTTP_AUTHORIZATION`. When the front controller is `/index.php` and `DirectoryIndex` is absent, `/` uses `index.php`.

The `.htaccess` watcher recompiles only when a file named `.htaccess` changes. A comment purges that post URL. A menu purges the tag `menu`. A URL that is not in the cache does not empty the site.

`Server` and `exyonq --version` use `EXYONQ_ARTIFACT_VERSION`.
