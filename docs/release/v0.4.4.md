# ExyonQ v0.4.4

Published release. Tag `v0.4.4` is `8f3336f783dc546bdaad4a60b5501568bf688b3a`. GitHub Release: https://github.com/ExyonQ/ExyonQ/releases/tag/v0.4.4. Image: `ghcr.io/exyonq/exyonq:0.4.4` (`sha256:4f69f9e7e7c817d1d45733ab796f992261f686fc1d1c657ba28aa5d1936cd983`), plus `0.4.4-amd64` and `0.4.4-arm64`.

## Changes

- Workspace product version **0.4.3 → 0.4.4**.
- Rust toolchain **1.98.1**.
- Production Linux binaries are musl and statically linked (`scripts/release/build-production.sh`).
- Dependency line: Wasmtime 49.0.1, quiche 0.30.0, s2n-quic 1.89.0, tachyon-quic 0.3.0, rustls 0.23.45, hyper 1.11.1, OpenTelemetry 0.33.0, redis 1.7.1.
- `instant-acme` stays on the published 0.8.5 API. `third_party/instant-acme` is that release with `base64` 0.23, because 0.9.0 is not on crates.io.
- Dataplane fixes reproduced by independent Netcup oracles: static host routing, epoll inline access and request id, wire metrics, proxy upstream body completion, WAF challenge host, compression and rate-limit exemptions.

## Release workflow fix

The first tagged commit failed `cargo build --locked` because `Cargo.lock` still said `0.4.3` and still listed `exyonq-bench`, which is no longer in the workspace. It also lacked `docs/security/audit-v0.4.4.md` and this file, so `security-release` and `github-release` could not finish. The image job waits on `compliance-artifacts`, which waits on `security-release`, so the image was not pushed either.

The corrected candidate syncs the lock to `0.4.4`, drops `exyonq-bench`, adds those two documents, accepts `0.4.4` in the release manifest allowlist, and removes unused `write_raw_proxy_response` so `-Dwarnings` can pass.

## Security

- Audit: `docs/security/audit-v0.4.4.md`.
- RUSTSEC-2026-0222 was waived for v0.4.3 only (Wasmtime 45.0.2). The v0.4.4 pin is Wasmtime 49.0.1, inside the published patched range `>=47.0.3`. The waiver is not renewed.
- Local `cargo audit` on 2026-10-01 reported no vulnerabilities and one allowed yanked-crate warning (`yoke-derive` 0.8.3). `cargo deny check advisories bans sources` reported advisories, bans, and sources ok.
- Nightly fuzz, the security integration tests, and a full unsafe review of the product delta were not run for this repair.
