## Why this release

0.6.0 publishes operational surfaces on top of the 0.5.0 tree: fail-closed `.htaccess` diagnostics, cache observability (`X-Cache` and ctl explain), WebSocket reload/drain guarantees, config explain provenance, reload route diff, FastCGI pool diagnostics, plus `Expires`/`cache_headers` and `response_headers` work already present on the 0.5.x line. Product version advances so addon `core_compat` can cover `0.6.x`.

## Shipped

1. Product version **0.6.0**.
2. Official modules: `core_compat = ">=0.1.0, <0.7.0"`.
3. Linux amd64/arm64 binaries on the GitHub Release.
4. Images `ghcr.io/exyonq/exyonq:0.6.0.1` and `ghcr.io/exyonq/exyonq-wordpress:0.6.0.1` (and Docker Hub mirrors), multi-arch, no `:latest`. GitHub release/source archive: **v0.6.0.1**. Docker Hub tags `:0.6.0` were removed.

## E2E checks (required before publish)

- `exyonq`: container stays up, GET `/` → 200 (amd64 + arm64)
- `exyonq-wordpress`: installer creates an account, login sets `wordpress_logged_in_*`, GET `/wp-admin/` with that cookie is the dashboard (amd64 + arm64)
