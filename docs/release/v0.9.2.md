## Included in this draft

1. **WordPress cache invalidation as a normal plugin.** The integration is
   loaded through the standard WordPress plugin lifecycle instead of as a
   must-use plugin, so activation and update flows use the normal plugin path.
   (`ab0e166`)
2. **SSH v2 artifact signatures.** The release verifier now supports SSH
   signatures and the release signer trust policy. This is release tooling, not
   a change to the HTTP server. (`4956073`)
3. **Artifact-bound OL-04/OL-03 E2E.** A dedicated workflow and negative
   control bind the tested binary hash to the evidence logs. (`731da56`,
   `524b0d3`)
4. **OL-03 OpenLiteSpeed readiness.** The comparison waits for OLS to answer
   HTTP instead of treating an open TCP port as ready, and asserts only the
   documented `perClientConnLimit` contract. (`9550d7e`)
5. **WAF/OL-05 evidence.** The final revalidation and reCAPTCHA v3 status are
   recorded; the positive v3 path still requires a real v3 key. (`38fdb74`)
6. **Release evidence update.** The 0.9.1 image status and security audit were
   updated after the 0.9.1 release. (`4cdad85`)
7. **CI oracle pinning.** The CI job invokes the OL-03 comparison against the
   OpenLiteSpeed image by immutable digest; the launcher and the comparison
   reject mutable tags.
8. **Security audit 2026-11-07 remediation (H-01…H-10).** H-02, H-03, H-04,
   H-05, H-07, H-09 and H-10 harden request-body budgets, forwarded headers,
   WAF defaults, HTTP/3 0-RTT, wire parsing, SNI wildcards and static file
   errors; H-06 pins the security-tool versions. H-01 fixes release-note drift.
   The item list and the open signing gap are in the 0.9.2 changelog entry.
   `[[route]].max_request_body_bytes` bounds WAF inspection cost with a `413`
   before inspection and upstream dispatch, while unset routes keep the 64 MiB
   contract.
9. **Purge token survives restarts.** The WordPress entrypoint reuses the
   `EXYONQ_CACHE_PURGE_TOKEN` already present in `wp-config.php` instead of
   regenerating it on every boot. In the published 0.9.1 image the regenerated
   token left the mu-plugin with a stale value, so every purge returned
   `unauthenticated` after a restart. Found while running the 0.9.1 Docker Hub
   digest E2E (`docs/releases/0.9.1-ghcr-publication.md` §7.3); not fixed in any
   published image yet.
