# ExyonQ 0.9.3

Released 2026-11-19. Built from the tagged commit in the public tree, not from a
local checkout.

## What changed since 0.9.2

- **WAF and access logs carry request context.** Access events include `host`;
  WAF violation events include `client_ip`, `host`, `method`, `path` and
  `user_agent`, and the abuse trace carries the same context. A violation can
  now be attributed to a site and joined with its access line without inferring
  the site from the path (issue #84).
- **The packaged PHP-FPM healthcheck discovers the unit.** It resolves active
  `php*fpm*` units instead of pinning a versioned name, accepts an exact unit
  override or `off`, optionally probes the PHP-FPM Unix socket, and fails with
  the candidate list when units are installed but none is active (issue #81).
  `EXYONQ_HEALTHCHECK_UNITS=none` runs the HTTP probes without systemd.
- **`wasmtime` 49.0.6 replaces 49.0.5.** RUSTSEC-2026-0566 through `-0572` were
  published against 49.0.5; the fix release is in the same minor line, so no API
  migration was needed. `deny.toml` keeps `ignore = []`: no advisory waiver was
  added.

## Verified before the tag

`cargo deny check` reports `advisories ok, bans ok, licenses ok, sources ok`,
`cargo audit` reports no vulnerabilities, `cargo fmt --all` is clean, clippy
passes with `-D warnings` for `exyonq-core` and `exyonq-wasm-host`, the core
library suite passes (254 tests), and `cargo check --workspace --all-targets
--locked` succeeds. CI on the parent commit ran the full workflow green,
including `supply-chain`.

## Known limitations

- The Docker Hub mirror is not published by `release.yml`; it needs
  `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` and a digest-preserving mirror step.
- The cosign artifact layer required by `security/signing/TRUST-POLICY.md`
  (`COSIGN_ARTIFACT_LAYER = RETAINED_REQUIRED_FOR_OFFICIAL_RELEASE`) is still
  absent: cosign is not installed and there is no private key.
- `exyonq validate` remains transitional; `exyonqctl config lint` and
  `exyonqctl config test` are the supported commands.
- The audit document records the toolchain evidence that existed at seal time.
  `cargo-geiger` is inconclusive by construction (coverage warnings mean unsafe
  counts are a lower bound) and `veyra-e2e` is skipped for lack of declared
  scenarios; neither is reported as a pass.

## Not part of this release

No WordPress image rebuild, no Docker Hub mirror, no Scout scan and no
independent COMPAT review. Those remain open on the roadmap.
