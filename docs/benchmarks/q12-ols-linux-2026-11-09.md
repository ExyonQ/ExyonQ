## Method

- All servers run natively on the same host and kernel, read the same payload
  files from one directory, use HTTP/1.1 keep-alive and disable access logging.
- OLS is an already-running native process. The harness rejects non-loopback
  URLs; a container, VM or remote endpoint is not comparable.
- Warm-up: 2 s per server/payload before the measured repetitions.
- Each repetition starts a fresh 5 s closed-loop `oha` run; server order
  rotates per repetition to spread drift. `oha` 1.14 has no thread selector:
  concurrency is the declared connection count.
- Every response is validated by `oha` (status 200, success rate 1.0, no
  errors) and, before measurement, by an exact SHA-256 body oracle per
  server/payload.

## Limitations

- Native Ubuntu 24.04.5 LTS (x86_64) on a shared GitHub-hosted runner; absolute
  numbers are not portable and runner noise is part of the result.
- OpenLiteSpeed was installed as a native package in CI and started from the
  tracked `scripts/bench/openlitespeed/` config with gzip disabled. This does
  not establish a native OLS build for the reference macOS host.
- This run is separate from the branch baseline run `42695705050`; the host CPU
  model differs, so numbers must not be compared across the two runs as if
  they were one controlled experiment.
- The intervals overlap; the report is an engineering baseline, not a ranking.
- There is still no `main` baseline and therefore no passing PR regression
  gate; `origin/main` is 0.9.1 and does not contain 0.9.2.
